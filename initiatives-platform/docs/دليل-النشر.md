# دليل النشر

## النشر على Netlify مع Supabase (الوضع السحابي)

1. **Supabase**: الهجرات في `supabase/migrations/` مطبقة بالترتيب (0001 → 0007)،
   وEdge Function في `supabase/functions/admin-users/` منشورة. للتكرار على مشروع جديد:
   طبّق الملفات نفسها عبر SQL Editor أو Supabase CLI ثم انشر الدالة.
2. **Netlify — إنشاء الموقع**: اربط المستودع، واضبط:
   - Base directory: `initiatives-platform`
   - (سيقرأ Netlify تلقائيًا `netlify.toml`: build = `node tools/gen-config.mjs`, publish = `.`)
3. **متغيرات البيئة في Netlify** (Site settings → Environment variables):
   - `SUPABASE_URL` — رابط المشروع
   - `SUPABASE_ANON_KEY` — المفتاح القابل للنشر فقط (anon/publishable) — **ليس service_role أبدًا**
   - `STORAGE_MODE` = `supabase`
4. **Supabase Auth URLs** (Authentication → URL Configuration):
   - Site URL: رابط موقع Netlify (مثال `https://your-site.netlify.app`)
   - Redirect URLs: أضف الرابط نفسه + `/login.html`
5. انشر، ثم تحقق: الدخول بحساب جهة، وعدم ظهور مبادرات الجهات الأخرى، وعمل المرفقات بروابط موقعة.

> المنصة متعددة الصفحات مع Hash Routing داخل `app.html` — تحديث الصفحة على أي مسار داخلي
> لا ينتج 404 (لا توجد مسارات History API)، والمسارات غير الموجودة تعرض `404.html` العربية.

## النشر المحلي/التجريبي (بلا خادم)

## GitHub Pages (الوضع الحالي)
المنصة تعيش في مجلد `initiatives-platform/` داخل مستودع منصة المواقع الاستثمارية،
ويُنشر المستودع كاملًا عبر `.github/workflows/deploy.yml`:

1. **checks**: فحوص التطبيق الأصلي كما هي دون تغيير.
2. **checks-initiatives**: من داخل `initiatives-platform/` تُنفَّذ
   `npm ci` ثم `lint` و`test` و`test:e2e` و`check` و`validate:links`
   والتحقق من وجود الملفات الأساسية وخلو الصفحات من مسارات جذر النطاق.
3. **deploy**: لا يعمل إلا بعد نجاح المرحلتين، ويرفع المستودع كاملًا كـ Pages Artifact.

الرابط بعد النشر: `https://<user>.github.io/<repo>/initiatives-platform/`

### إعداد يدوي لمرة واحدة
في إعدادات المستودع ‏> Pages ‏> Source: اختر **GitHub Actions**
(إن كان النشر سابقًا من فرع، حوّله — وإلا فلن يعمل deploy-pages).

## لماذا تعمل تحت مسار فرعي؟
- كل المسارات نسبية (`./…`) — ممنوع أي `href="/…"` (يفحصه CI).
- التوجيه الداخلي عبر Hash (`app.html#/dashboard`) فلا يحتاج إعادة توجيه خادمية.
- `manifest.webmanifest`: ‏`start_url` و`scope` نسبيان (`./`).
- Service Worker مسجَّل بنطاق `./` فلا يمس بقية المستودع.

## النقل إلى مستودع مستقل
```bash
# انسخ المجلد كاملًا إلى مستودع جديد
cp -r initiatives-platform/* new-repo/
```
لا شيء داخل المجلد يعتمد على خارجه — أضف للمستودع الجديد Workflow نشر بسيطًا
(upload-pages-artifact بمسار `.`) وستعمل من `https://<user>.github.io/<new-repo>/`.

## أي استضافة ثابتة أخرى
ارفع محتوى المجلد لأي خادم ملفات (Netlify، Cloudflare Pages، خادم داخلي).
لا متطلبات سوى تقديم `.webmanifest` بأي نوع محتوى معقول.

## قائمة تحقق ما قبل النشر
- [ ] `npm run lint && npm test && npm run test:e2e && npm run check && npm run validate:links`
- [ ] لا `config.local.js` في الحزمة (تفحصه `.gitignore`).
- [ ] جرّب الرابط العميق `app.html#/initiatives/MDN-INIT-2026-0001` بعد النشر.
- [ ] جرّب تحديث المتصفح داخل التطبيق (يجب ألا يظهر 404).
