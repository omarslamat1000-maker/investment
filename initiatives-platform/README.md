# منصة مبادرات البنية التحتية والشراكات المجتمعية

**أمانة منطقة المدينة المنورة** — تطبيق ويب عربي RTL مستقل بالكامل لحوكمة مبادرات البنية التحتية
والشراكات مع القطاع الخاص والمجتمع، عبر بوابات مرحلية (Stage-Gates) وإدارة منافع (Benefits Realization).

> المنصة تعمل داخل المجلد `initiatives-platform/` باستقلال تام عن أي تطبيق آخر في المستودع،
> ويمكن نسخ المجلد إلى مستودع آخر وتشغيله كما هو.

## المزايا

- **بوابة عامة** (`index.html`): فرص البنية التحتية المطروحة للشراكة، الحملات، رحلة البوابات، ومؤشرات معلنة.
- **تقديم مبادرات** (`submit.html`): معالج من 4 خطوات بتحقق كامل ورقم متابعة رسمي `MDN-INIT-YYYY-NNNN`.
- **تتبع الحالة** (`initiative-details.html`): حالة المبادرة على مسار البوابات برقم المتابعة.
- **بوابة الشركاء** (`partner-portal.html`): مبادرات كل جهة ومساهماتها ومنافعها المعلنة.
- **تطبيق إدارة** (`app.html`): لوحة متابعة، سجل مبادرات، احتياجات، شركاء، مراجعات، قرارات،
  تنفيذ، منافع، مخاطر، جودة، خريطة، تقارير، إعدادات — بموجّه Hash متوافق مع GitHub Pages.
- **حوكمة Stage-Gate**: خمس بوابات (G0 فرز، G1 جدوى، G2 اعتماد، G3 جاهزية، G4 منافع وإقفال)
  بقوائم تحقق وقرارات مسببة وسجل تدقيق.
- **مفاضلة موزونة**: 5 معايير بأوزان مجموعها 100 (توافق استراتيجي 25، أثر مجتمعي 25، جدوى 20، جاهزية شريك 15، مخاطر 15).
- **تخزين محلي مستقل**: قاعدة IndexedDB باسم `madinah-initiatives-platform-db` مع بنية ترحيلات،
  ومزوّد Supabase اختياري بنفس العقد.
- **دون اتصال**: Service Worker بنطاق `./` وأسماء Cache ببادئة `madinah-initiatives-platform-`.
- **نسخ احتياطي**: تصدير/استعادة JSON بمخطط موثّق واسم تطبيق ومجموع تحقق.

## التشغيل المحلي

```bash
cd initiatives-platform
npm install   # لا اعتمادات — تهيئة فقط
npm run serve # http://localhost:8210/
```

أو بأي خادم ملفات ثابت:

```bash
cd initiatives-platform
python -m http.server 8000
```

ثم افتح `http://localhost:8000/`.

## الفحص والاختبار

```bash
npm run lint            # صياغة 75 ملف JavaScript
npm test                # 78 اختبار وحدة وتكامل (node:test)
npm run test:e2e        # 18 اختبار E2E على خادم حقيقي
npm run check           # فحوص الاستقلالية (قاعدة، SW، مفاتيح، مسارات نسبية)
npm run validate:links  # كل رابط ومورد محلي يشير لملف موجود
```

## البنية

| المسار | الدور |
|---|---|
| `js/core/` | ثوابت، أدوات، تحقق، تعقيم، صلاحيات، أحداث، حالة، تاريخ/وقت |
| `js/data/` | مزوّدا IndexedDB وSupabase، المستودعات، الترحيلات |
| `js/domain/` | نماذج المبادرة/الاحتياج/الشريك، سير العمل، البوابات، المفاضلة، المنافع، المخاطر، الصحة |
| `js/modules/` | شاشات التطبيق (لوحة، مبادرات، احتياجات، …) |
| `js/services/` | مرفقات، استيراد/تصدير، طباعة، تدقيق، نسخ احتياطي، إشعارات |
| `js/ui/` | مكوّنات، حوارات، تنبيهات، جداول، معالج نماذج، رسوم، إتاحة |
| `data/` | البيانات التجريبية والمرجعية |
| `supabase/` | مخطط SQL وسياسات RLS وبذور — للتفعيل الاختياري |
| `docs/` | أدلة المستخدم والحوكمة والنشر وقاموس البيانات |
| `tests/` | unit + integration + e2e |

## الأدوار (نسخة عرض بلا مصادقة)

مدير النظام، مكتب إدارة المبادرات، عضو لجنة المراجعة، مشرف التنفيذ، شريك، مطَّلع —
يبدَّل الدور من «الإعدادات» وتتغير الصلاحيات الظاهرة وفق `js/core/permissions.js`
(انظر `docs/مصفوفة-الصلاحيات.md`).

## الإعدادات

انسخ `js/config.example.js` إلى `js/config.local.js` للتخصيص المحلي (الملف خارج المستودع عبر `.gitignore`).
لا تضع مفاتيح Supabase في `config.example.js` إطلاقًا.

## الترخيص

عمل داخلي لأغراض العرض — البيانات المضمنة توضيحية ولا تمثل جهات أو مشاريع حقيقية.
